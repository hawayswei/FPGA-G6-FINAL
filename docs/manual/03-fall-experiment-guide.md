# 跌倒實驗手冊：錄資料與統計（組員版）

這份手冊教你做兩件事：

1. **錄資料**：配戴感測器做一個動作（跌倒或日常動作），把這段時間的三軸加速度存成一個檔案。
2. **統計**：把所有錄好的檔案交給程式，得到每種動作的數據、偵測率、誤報率，以及建議的閾值。

照順序做。**畫面上的文字若和手冊不同，或出現紅色錯誤訊息，截圖給整合者，不要自己改程式。**

> 重要：錄資料用的 Vivado 指令（第 4 節）是在沒有板子的情況下寫的，還沒有實際測過。第一次使用時很可能要修正，請把出現的訊息回報給整合者。統計程式（第 6 節）已經用假資料測過。

## 1. 沒有板子也能先試：用假資料跑一次統計

這一步只需要電腦和 Python，用來熟悉統計程式的用法。

1. 開啟命令提示字元（或 PowerShell），切到 repo 資料夾：

   ```
   cd /d D:\FPGA\FPGA-G6-FINAL
   ```

2. 產生假資料（42 個檔案，放在 `data\demo_trials\`）：

   ```
   python tools\make_demo_trials.py
   ```

3. 跑統計：

   ```
   python tools\analyze_trials.py data\demo_trials
   ```

4. 畫面會印出報表，同樣的內容存在 `data\demo_trials\_report\summary.txt`。

**假資料是用簡單的形狀加雜訊捏出來的，不能寫進報告，也不能拿來決定閾值。** 它只用來練習操作。

## 2. 第一次要安裝的東西

| 項目 | 怎麼裝 | 用途 |
|---|---|---|
| Python 3.9 以上 | 到 python.org 下載安裝，安裝時勾選 *Add Python to PATH* | 跑統計程式 |
| matplotlib（建議） | 命令提示字元輸入 `pip install matplotlib` | 畫每次動作的波形圖。沒裝也能跑，只是沒有圖 |
| Vivado 2019.2 | 課程已安裝 | 錄資料 |

確認 Python 裝好：命令提示字元輸入 `python --version`，要看到版本號。

## 3. 實驗前的準備與安全

**安全第一。這是模擬跌倒，不是真的摔。**

- 在厚軟墊上做（體操墊、床墊）。周圍一公尺內不要有桌角、椅子、硬物。
- 至少兩個人：一個人做動作，一個人操作電腦並注意安全。
- 有任何不舒服就停止。不要為了數據做出勉強的動作。
- 線要留足長度並固定在手臂上，避免跌倒時扯到板子。板子放在不會被壓到、拉下桌的位置。

**硬體準備：**

1. 照《上板測試手冊》（`02-board-test-guide.md`）第 3 節接好加速度計，並確認 LD1 恆亮。
2. 把感測器模組牢牢固定在**上臂外側**。用魔鬼氈或彈性繃帶，模組不能晃動。
3. **每次實驗都固定在同一個位置、同一個方向**，並拍一張照片存檔。方向不同，三軸的數值會完全不同。
4. 板上兩個滑動開關 SW0、SW1 都撥到**下方（0）**。SW0 在上方時，讀到的是假資料。

## 4. 錄一次動作

### 4.1 每次開 Vivado 後做一次

1. 板子接上 USB（PROG UART 孔），開電。
2. 開啟 Vivado 2019.2。**不需要開專案。**
3. 在視窗最下方的 **Tcl Console** 輸入（斜線用 `/`）：

   ```
   source D:/FPGA/FPGA-G6-FINAL/scripts/capture.tcl
   ```

4. 再輸入：

   ```
   cap_connect
   ```

   它會連上板子並燒錄。看到 `CAPTURE: board programmed, ILA ready` 就完成了。

   如果出現 `Bitstream not found`，代表你的電腦還沒產生過燒錄檔。先照《上板測試手冊》第 4 節做一次 Generate Bitstream。

### 4.2 每做一個動作

1. 做動作的人就定位，站好不動。
2. 操作電腦的人在 Tcl Console 輸入一行，例如：

   ```
   cap fall_front A 01
   ```

   四個欄位依序是：**動作名稱、誰做的、第幾次**，最後可以再加秒數（不寫就是 10 秒）。

3. 按下 Enter 後畫面出現 `>>> DO THE ACTION NOW <<<`，**這時才開始做動作**。建議流程：
   - 先站著不動 3 秒
   - 做動作
   - 做完後**保持不動**直到錄完（跌倒後躺著不動；日常動作做完後維持姿勢）
4. 約 10 秒後出現 `CAPTURE: saved ...`，檔案就存好了。
5. 下一次把最後的數字加一：`cap fall_front A 02`。

**同樣的檔名不會被覆蓋。** 出現 `File already exists` 就換下一個號碼。錄壞的檔案請直接刪掉那個 `.csv`，並記在實驗紀錄裡。

錄製秒數可以選 10、20、40、80，例如走路想錄久一點：`cap adl_walk A 01 20`。

## 5. 檔名規則與要錄的動作

### 5.1 檔名

`動作_人_編號.csv`，全部用英文和數字，**人的代號裡不要有底線**。

- 動作名稱以 `fall` 開頭 → 程式當作「跌倒」（應該要被偵測到）。
- 其他開頭 → 程式當作「日常動作」（不應該被偵測到）。

### 5.2 建議的動作清單（對應提案書第參節的驗證方法）

| 動作名稱 | 內容 | 每人次數 |
|---|---|---|
| `fall_front` | 向前倒 | 5 |
| `fall_back` | 向後倒 | 5 |
| `fall_left` | 向左側倒 | 5（左右合計至少 5） |
| `fall_right` | 向右側倒 | 同上 |
| `adl_walk` | 走路 | 20（可用 20 秒錄一次，連續走） |
| `adl_sit` | 坐下 | 20 |
| `adl_stand` | 起身 | 20 |

可以自己加動作，例如 `adl_wave`（揮手）、`adl_clap`（拍手）、`adl_stairs`（上下樓梯）、`adl_liedown`（慢慢躺下）。手臂的日常動作多，這些最容易造成誤報，值得多錄。

### 5.3 實驗紀錄

另外用紙或試算表記下：日期、誰做的、身高、感測器位置照片檔名、每一筆的檔名與備註（例如「這次手先撐地」、「錄壞了已刪除」）。報告會用到。

## 6. 跑統計

1. 開啟命令提示字元，切到 repo：

   ```
   cd /d D:\FPGA\FPGA-G6-FINAL
   ```

2. 執行：

   ```
   python tools\analyze_trials.py data\trials
   ```

3. 可以加的選項：

   | 選項 | 意思 | 例子 |
   |---|---|---|
   | `--mode` | 使用者模式：`adult`（預設）、`elderly`、`sport` | `--mode elderly` |
   | `--height` | 身高（公分），預設 170 | `--height 160` |
   | `--posture` | 判定時多要求「姿勢有改變」 | `--posture` |
   | `--no-plots` | 不畫圖（比較快） | `--no-plots` |

   例如：`python tools\analyze_trials.py data\trials --mode elderly --height 160`

4. 結果在 `data\trials\_report\`：

   | 檔案 | 內容 |
   |---|---|
   | `summary.txt` | 總報表（和畫面上印的一樣） |
   | `trials.csv` | 每一筆動作一列的數據，可用 Excel 開 |
   | `plots\*.png` | 每一筆的波形圖（要裝 matplotlib） |
   | `scatter.png` | 所有動作的散佈圖（要裝 matplotlib） |

## 7. 報表怎麼看

### 7.1 `summary.txt` 的四個區塊

1. **Per action（每種動作）**：每種動作的平均、最小、最大值。

   | 欄位 | 意思 | 跌倒時通常 |
   |---|---|---|
   | lowest \|a\| before peak (g) | 撞擊前合成加速度的最低點 | 很低（接近 0，失重） |
   | peak \|a\| (g) | 合成加速度最高點 | 很高（撞擊） |
   | lowest -> peak (s) | 最低點到最高點的時間 | 零點幾秒 |
   | free fall (ms) | 連續低於 0.5 g 的最長時間 | 一兩百毫秒以上 |
   | moving fraction after impact | 撞擊後 1 到 3 秒內「還在動」的比例 | 接近 0（躺著不動） |
   | posture change (deg) | 動作前後重力方向差幾度 | 大（從站變躺） |

   靜止不動時合成加速度是 1 g。

2. **Result with the settings above**：用目前設定的閾值，程式模擬 FPGA 的判定結果。
   - *Falls detected*：跌倒被偵測到的比例，目標 ≥ 90%。
   - *False alarms*：日常動作被誤判的比例，目標每種動作 ≤ 5%。
   - *Missed falls*、*False alarms* 後面列出是哪幾個檔案，可以去看那幾張波形圖。

3. **Threshold sweep（閾值掃描）**：一張表。直的是撞擊閾值，橫的是失重閾值，每格是「偵測率 / 誤報率」。左邊數字越大越好，右邊越小越好。

4. **Suggested**：程式挑出的一組閾值，以及要填進 `rtl/fall/fall_param_lut.v` 的數字。**這只是起點**，資料少的時候很多組會同分。把這一段交給整合者，由整合者修改程式。

### 7.2 波形圖（`plots\`）

- 上圖：黑線是合成加速度。藍色虛線是失重閾值，紅色虛線是撞擊閾值，綠色直線是 FPGA 會回報跌倒的時間點。
- 下圖：X（紅）、Y（綠）、Z（藍）三軸各自的數值。
- 典型跌倒：黑線先掉到藍線以下，接著衝過紅線，然後回到 1 g 附近變平。

### 7.3 散佈圖（`scatter.png`）

每個點是一筆動作。橫軸是最低點，縱軸是最高點。紅點（跌倒）應該集中在**左上角**，藍點（日常動作）在其他地方。兩群分得越開，閾值越好選；如果混在一起，代表只靠這兩個數字不夠，要靠「靜止」與「姿勢」條件來區分。

## 8. 出問題怎麼辦

| 現象 | 處理 |
|---|---|
| `cap_connect` 說找不到板子 | USB 線要插 PROG UART 孔；板子要開電；關掉其他開著的 Vivado 視窗後重試 |
| `Bitstream not found` | 先做《上板測試手冊》第 4 節的 Generate Bitstream |
| `cap` 之後一直沒有 `saved`，等很久 | 資料沒有進來。看板上 LD1 有沒有亮；沒亮是感測器接線問題。SW0 撥到上方可以用假資料確認流程 |
| `cap` 出現紅色錯誤，內容有 `property` 或 `hw_probes` | 腳本需要修正。把整段紅字複製給整合者 |
| 統計程式說 `cannot find x / y / z columns` | 那個 CSV 的格式和預期不同。把該檔案傳給整合者 |
| 統計程式說 `no .csv files` | 資料夾路徑打錯，或還沒錄過 |
| 波形是一直線、數值都是 0 | 感測器沒有進入量測狀態。按一下 BTN3 重置後重錄 |
| 靜止時合成加速度不是約 1 g | 回報整合者（量程設定可能要調整） |
| 圖沒有產生 | 沒裝 matplotlib：`pip install matplotlib` |

## 9. 沒有感測器時測試整個流程

板上的 **SW0 撥到上方**，FPGA 會改用內建的假資料：每約 21 秒重複一次「站立 15 秒 → 失重 → 撞擊 → 躺著 6 秒」。這時不接感測器也可以：

1. 用 `cap test_sw0 X 01 40` 錄 40 秒，確認檔案會產生。
2. 用 `python tools\analyze_trials.py data\trials` 確認程式讀得懂這個檔案。
3. 觀察板子：假跌倒發生約 3 秒後 LD2 開始閃（詢問中），10 秒內按 BTN0 可以取消；不按則 LD3 亮（警報）。

測完記得把 `test_sw0_*.csv` 刪掉，並把 SW0 撥回下方。

1. `data\trials\` 裡所有的 `.csv`（用 git 存檔上傳到自己的分支，檔案很小）。
2. `data\trials\_report\summary.txt` 的內容。
3. 實驗紀錄（第 5.3 節）與感測器位置的照片。
